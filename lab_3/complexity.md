# Анализ сложности алгоритмов

`n` - количество элементов массива или символов строки. Ниже приведены оценки для худшего случая без учета чтения, разбора и вывода данных.

## 1. Сортировка массива

- **Время:** **O(n log n)** при сравнении за **O(1)**. Для строк - **O(C · n log n)**, где `C` - стоимость сравнения строк через `localeCompare`, зависящая от их длины
- **Дополнительная память:** **O(n)** на копию массива `[...array]` и рабочую память сортировки в Node.js (V8)
- Оценки `sort()` относятся к реализации в Node.js (V8); стандарт JavaScript не гарантирует конкретную сложность этого метода



## 2. Бинарный поиск

- **Время самого поиска:** **O(log n)** - на каждом шаге диапазон уменьшается вдвое
- **Дополнительная память самого поиска:** **O(1)** - используются только переменные границ и середины
- **С учетом подготовки:** проверка целых чисел через `every()` занимает **O(n)**, сортировка - **O(n log n)**. Итого **O(n log n)** по времени и **O(n)** дополнительной памяти для сортировки в Node.js (V8)



## 3. Проверка сбалансированности скобок

- **Время:** **O(n)** - каждый символ обрабатывается один раз; операции со стеком занимают амортизированное **O(1)**
- **Дополнительная память:** **O(n)** - в худшем случае все символы являются открывающими скобками и сохраняются в стеке
