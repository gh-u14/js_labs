# Анализ сложности алгоритмов

`n` - количество элементов массива, `k` - размер top-k / ограничение на размер кучи. Ниже приведены оценки для худшего случая без учета чтения, разбора и вывода данных. Сравнения чисел считаются за **O(1)**.

## 1. Пирамидальная сортировка (Heap Sort)

- **`buildHeap`:** **O(n)** - просеивание вниз от середины массива; сумма высот узлов ограничена линейно
- **`siftDown` / `siftUp`:** **O(log n)** - высота бинарной кучи
- **`heapSort`:** **O(n log n)** - построение кучи **O(n)** плюс **n - 1** извлечений корня с просеиванием **O(log n)** каждое
- **Дополнительная память:** **O(n)** на копию массива `[...array]`; сама сортировка in-place по рабочей копии использует **O(1)** сверх неё (без рекурсии)



## 2. Top-k сверху (k наибольших)

- Алгоритм: Min Heap размера не больше `k`
- **Время:** **O(n log k)** - для каждого из `n` элементов не более одного `siftUp` / `siftDown` по куче высоты **O(log k)**
- **Дополнительная память:** **O(k)** на кучу; финальная сортировка результата - **O(k log k)** по времени и не меняет асимптотику дополнительной памяти
- При `k ≪ n` выгоднее полной сортировки **O(n log n)**



## 3. Top-k снизу (k наименьших)

- Алгоритм: Max Heap размера не больше `k` (симметрично 2 задаче)
- **Время:** **O(n log k)**
- **Дополнительная память:** **O(k)**



## 4. Priority Queue

Оценки на одну операцию при текущем размере очереди `m` (в худшем случае `m` доходит до числа всех `enqueue`):

- **`enqueue`:** **O(log m)** - `push` + `siftUp`
- **`dequeue`:** **O(log m)** - замена корня последним элементом + `siftDown`
- **`peek` / `size` / `isEmpty`:** **O(1)**
- **Дополнительная память:** **O(m)** на хранение элементов в массиве-куче
